# 会議室管理システム

## 1. サービス概要

本サービスは、会議室の予約情報や利用状況を一元管理できるWebアプリケーションです。

ユーザー登録・ログイン後、会議室情報や予約情報の登録・確認・編集・削除を行えます。

紙やExcelによる二重管理や情報共有の手間を減らし、会議室管理業務の効率化を支援します。

### 誰の、どんな課題を、どう解決するか

事務担当者や会議室管理者が抱える、紙やExcelによる予約管理や情報共有の負担を、会議室予約情報の一元管理によって解決します。

予約状況を画面から確認できるようにすることで、管理業務の効率化と業務負担の軽減を目指します。

---

## 2. このサービスを作ろうと思った理由

### 2-1. きっかけとなった体験・感情

新卒で勤務していた健康食品会社では、毎朝会議室や共有スペースの清掃を担当していました。

しかし、会議室の利用状況を確認する仕組みがなかったため、利用されていない部屋も含めて清掃を行っていました。

その経験から、「会議室の利用状況が分かれば、必要なタイミングで管理業務や清掃を行えるのではないか」と感じました。

また、利用履歴や予約情報を一元管理できれば、清掃だけでなく、設備運用や情報共有などの管理業務全体の効率化につながるのではないかと考え、本サービスを着想しました。

### 2-2. なぜそれが気になったのか

私は効率的に業務を進めることを重視しています。

実際には利用されていない部屋も含めて清掃や管理業務を行っていたため、毎日約30分の時間と労力を要していました。

会議室の利用状況や予約情報を可視化できれば、必要なタイミングで適切な対応が可能となり、業務全体の効率化につながると考えました。

---

## 3. 解決したい課題

### 3-1. 表に見えている困りごと

会議室の利用状況をすぐに把握できないため、管理業務や情報共有に手間がかかっていました。

また、紙やExcelによる管理では、予約状況の確認や利用履歴の把握に時間がかかっていました。

### 3-2. 本当に解決したい課題

なぜ？

→ 会議室の利用状況が分からなかったため。

なぜ？

→ 予約情報や利用履歴を簡単に確認できなかったため。

なぜ？

→ 情報が紙やExcelで管理され、一元化されていなかったため。

**本当に解決したい課題**

会議室の予約情報や利用履歴を一元管理・可視化することで、確認や情報共有にかかる手間を減らし、管理者が本来の業務に集中できる環境を実現することです。

## 4. 想定ユーザー

### 4-1. 想定しているユーザー

本サービスを利用するユーザーとして、以下を想定しています。

- オフィスワーカー
- 総務担当者
- 管理事務担当者

Excelや紙で会議室予約を管理している企業を主な対象としています。

特に、会議室の予約管理や情報共有を担当する管理者や事務担当者の業務負担軽減を想定しています。

### 4-2. 自分とユーザーの距離

**過去の自分**

新卒で入社した健康食品会社では、会議室の清掃業務を担当していました。

利用状況を確認する手段がなく、利用されていない部屋も毎日清掃していた経験があります。

この経験から、会議室利用状況の可視化によって無駄な作業を減らし、管理業務を効率化したいと考えました。

### 4-3. 実際に使われる可能性について

最初に利用するユーザーは、会議室や設備の管理を担当している総務担当者や管理事務担当者を想定しています。

また、実際の利用者としては、会議室を利用するオフィスワーカーや、管理業務に関わる担当者なども想定しています。

現在はExcel、紙の予約表、共有カレンダーなどで管理しているケースがあり、予約状況や利用履歴を一元管理できることで、業務負担の軽減につながると考えています。

特に、中小企業では管理業務を少人数で兼任している場合もあり、会議室管理専用のシステムを導入していないケースも想定されます。

本サービスでは、会議室の利用状況や予約情報を確認し、管理業務や情報共有の判断材料として活用されることを想定しています。

### 4-4. 導入・継続の流れ

#### 利用を始めるきっかけ

- 紙の予約表をExcelへ転記している
- 会議室管理に手間がかかっている
- 情報共有に時間がかかっている
- 管理業務によって本来の業務が圧迫されている

#### 導入の流れ

1. ユーザーアカウントを作成する
2. ログインする
3. 会議室情報を登録する
4. 予約情報を登録する
5. 会議室や予約の情報を確認・管理する

## 5. 競合調査

### 5-1. 調査したサービス

**サービス名：Colorkrew Biz**

#### 主な機能

- 会議室予約
- 空予約防止
- 自動キャンセル
- グループ予約
- Outlook連携
- Googleカレンダー連携

### 5-2. それでも自分が作りたい理由

既存サービスは、予約管理を中心に多くの機能を提供しています。

一方、私が実際に感じていた課題は、紙からExcelへの転記や、利用状況を確認するための情報共有など、会議室に関連する管理業務の負担でした。

そのため、本サービスでは予約管理を出発点として、将来的に利用履歴分析や清掃業務の判断支援へつなげることを目指しています。

### 5-3. 差別化ポイント

単なる会議室予約システムではなく、予約情報や利用履歴の可視化を通じて、管理業務の効率化を支援する点を特徴としています。

Googleカレンダーでも会議室をリソースとして登録し、予約管理を行うことは可能です。

しかし、Googleカレンダーはスケジュール共有を主な目的としており、会議室の利用状況をもとに管理業務や清掃業務を支援することに特化したサービスではありません。

本サービスでは、予約情報や利用履歴を一元管理・可視化することで、会議室の利用状況を把握しやすくし、紙やExcelによる管理や情報共有の負担軽減を目指しています。

また、将来的には利用履歴分析や清掃履歴管理など、会議室運用に関する業務支援機能の拡張を想定しています。

## 8. 懸念点と対策

### 懸念点

#### 機能追加による開発範囲の拡大

分析機能や清掃履歴管理などを同時に実装すると、MVPの完成が遅れる可能性がありました。

#### 公開環境でのSQLite利用

MVPではSQLiteを使用しているため、複数ユーザーによる同時利用や永続的な本番運用には課題があります。

#### 予約情報の公開範囲

現在は、認証済みユーザーが予約一覧および予約詳細を確認できる仕様です。

会議室の空き状況を確認するために予約時間の共有は必要ですが、将来的には予約状況として共有する情報と、予約者本人のみが確認できる詳細情報を分ける必要があります。

### 対策

MVPでは、会議室予約・管理に必要な機能に絞って実装しました。

分析機能や可視化機能などは、本リリース機能として段階的に実装します。

また、Docker対応後にPostgreSQLへ移行し、より本番運用に適した構成へ変更する予定です。

予約情報については、将来的に以下のように公開範囲を分けることを検討しています。

- 全利用者向け：会議室、開始日時、終了日時、予約状況
- 予約者本人向け：予約者情報、予約人数、編集・削除操作

## セットアップ方法

### 前提環境

- Python 3.14
- Poetry
- Git

### 1. リポジトリをクローン

```bash
git clone <リポジトリURL>
cd workspace_scheduler
```

### 2. 依存パッケージをインストール

```bash
poetry install
```

### 3. 環境変数ファイルを作成

`.env.example`をコピーして、`.env`を作成します。

```bash
cp .env.example .env
```

作成した`.env`に必要な環境変数を設定します。

### 4. マイグレーションを実行

```bash
poetry run alembic upgrade head
```

### 5. アプリケーションを起動

```bash
poetry run uvicorn backend.main:app --reload
```

### 6. ブラウザからアクセス

```text
http://127.0.0.1:8000
```

Swagger UIは以下から確認できます。

```text
http://127.0.0.1:8000/docs
```

### テストの実行

```bash
poetry run pytest
```

### カバレッジの確認

```bash
poetry run pytest --cov=backend
```

### RuffによるLintチェック

```bash
poetry run ruff check .
```
