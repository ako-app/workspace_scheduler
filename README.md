# 会議室管理システム

## 1. サービス概要

本サービスは、会議室の予約情報や利用状況を一元管理できるシステムです。

紙やExcelによる二重管理や情報共有の手間を減らし、管理業務の効率化を支援します。

会議室の利用状況を可視化することで、管理者が本来の業務に集中できる環境づくりを目指します。

### 誰の、どんな課題を、どう解決するか

事務担当者や会議室管理者が抱える、紙やExcelによる予約管理や情報共有の負担を、会議室予約情報の一元管理によって解決します。

予約状況や利用履歴を簡単に確認できるようにすることで、管理業務の効率化と業務負担の軽減を実現します。

---

## 2. このサービスを作ろうと思った理由

### 2-1. きっかけとなった体験・感情

新卒で勤務していた健康食品会社では、毎朝会議室や共有スペースの清掃を担当していました。

しかし、会議室の利用状況を確認する仕組みがなかったため、利用されていない部屋も含めて清掃を行っていました。

その経験から、「会議室の利用状況が分かれば、必要なタイミングで管理業務や清掃を行えるのではないか」と感じました。

また、利用履歴や予約情報を一元管理できれば、清掃だけでなく設備運用や情報共有などの管理業務全体の効率化につながるのではないかと考え、本サービスを着想しました。

### 2-2. なぜそれが気になったのか

私は効率的に業務を進めることを重視しています。

実際には利用されていない部屋も含めて清掃や管理業務を行っていたため、毎日約30分の時間と労力を要していました。

会議室の利用状況や予約情報を可視化できれば、必要なタイミングで適切な対応が可能となり、業務全体の効率化につながると考えました。

---

## 3. 解決したい課題

### 3-1. 表に見えている困りごと

会議室の利用状況が把握できないため、管理業務や情報共有に手間がかかっていました。

また、紙やExcelによる管理では、予約状況の確認や利用履歴の把握に時間がかかっていました。

### 3-2. 本当に解決したい課題

なぜ？
→ 会議室の利用状況が分からなかったため。

なぜ？
→ 予約情報や利用履歴を簡単に確認できなかったため。

なぜ？
→ 情報が紙やExcelで管理され、一元化されていなかったため。

**本当に解決したい課題**

会議室の予約情報や利用履歴を一元管理・可視化することで、確認や情報共有にかかる手間を減らし、管理者が本来の業務に集中できる環境を実現すること。

## 4. 想定ユーザー

### 4-1. 想定しているユーザー

本サービスを利用するユーザーとして、以下を想定しています。

* オフィスワーカー
* 総務担当者
* 管理事務担当者

Excelや紙で会議室予約を管理している企業を主な対象としています。

特に、会議室の予約管理や情報共有を担当する管理者や事務担当者の業務負担軽減を想定しています。

### 4-2. 自分とユーザーの距離

**過去の自分**

新卒で入社した健康食品会社では、会議室の清掃業務を担当していました。

利用状況を確認する手段がなく、利用されていない部屋も毎日清掃していた経験があります。

この経験から、会議室利用状況の可視化によって無駄な作業を減らし、管理業務を効率化したいと考えました。

### 4-3. 実際に使われる可能性について

最初に利用するユーザーは、会議室や設備の管理を担当している総務担当者や管理事務担当者を想定しています。

現在はExcel、紙の予約表、共有カレンダーなどで管理しているケースが多く、予約状況や利用履歴を一元管理できることで業務負担の軽減につながると考えています。

特に、中小企業では管理業務を少人数で兼任している場合も多く、会議室管理専用のシステムを導入していないケースもあるため、本サービスによる業務負担の軽減が期待できると考えています。

### 4-4. 導入・継続の流れ

#### 利用を始めるきっかけ

* 紙の予約表をExcelへ転記している
* 会議室管理に手間がかかっている
* 情報共有に時間がかかっている
* 管理業務によって本来の業務が圧迫されている

#### 導入の流れ

1. 管理者アカウント作成
2. 会議室情報登録
3. 利用者登録
4. 利用開始

## 5. 競合調査

### 5-1. 調査したサービス

**サービス名**: ColorkrewBiz

**できること**

* 会議室予約
* 空予約防止
* 自動キャンセル
* グループ予約
* Outlook連携
* Googleカレンダー連携

### 5-2. それでも自分が作りたい理由

既存サービスは予約管理に重点を置いています。

しかし私が感じていた課題は、紙からExcelへの転記や情報共有などの管理業務でした。

そのため、本サービスでは予約管理だけでなく、管理業務の負担軽減を重視しています。

### 5-3. 差別化ポイント

単なる会議室予約システムではなく、予約情報や利用履歴の可視化を通じて、管理業務の効率化を支援する点を特徴としています。

Googleカレンダーでも会議室をリソースとして登録し、予約管理を行うことは可能です。しかし、Googleカレンダーはスケジュール共有を主な目的としており、会議室管理や運用業務に特化したものではありません。

本サービスでは、予約情報や利用履歴を一元管理・可視化することで、会議室の利用状況を把握しやすくし、紙やExcelによる管理や情報共有の負担軽減を目指しています。

特に、会議室の利用状況が分からず、管理業務に時間を取られている総務担当者や管理事務担当者が、予約状況をすぐに確認し、本来の業務に集中できる環境を提供します。

また、将来的には利用履歴分析や清掃履歴管理など、会議室運用に関する業務支援機能の拡張も想定しています。

## 8. 懸念点と対策

### 懸念点

機能追加によってMVPの完成が遅れる可能性があります。

### 対策

まずは会議室予約・管理に必要な最小限の機能に絞り、MVPの完成を優先します。

分析機能や可視化機能などは、本リリース機能として段階的に実装する予定です。

## 10. 技術スタック

### 使用予定技術

#### バックエンド

* Python

  * 開発効率が高く、業務システムの開発や将来的なデータ分析に活用できるため採用。
* FastAPI

  * 一般的な構成で参考資料が豊富であり、効率的にAPIを開発できるため採用。

#### フロントエンド

* HTML
* CSS
* Jinja2
* JavaScript（必要に応じて使用）

  * 開発コストを抑え、バックエンド機能の実装に注力するため採用。

#### データベース

* PostgreSQL

  * 業務アプリケーションとの親和性が高く、信頼性の高いデータベースであるため採用。

#### ORM

* SQLAlchemy

  * FastAPIで一般的に利用されており、データベース操作や管理を効率的に行うため採用。

#### マイグレーション

* Alembic

  * SQLAlchemyと組み合わせて利用でき、データベースの変更管理を行いやすいため採用。

#### バリデーション

* Pydantic

  * 型定義とバリデーションを簡潔に実装できるため採用。

#### 認証

* JWT認証
* python-jose
* passlib[bcrypt]

  * FastAPIで一般的に利用されている構成であり、参考資料が豊富なため採用。
  * MVPでは、JWT認証やパスワードのハッシュ化を実装し、認証された利用者のみが会議室情報を閲覧・操作できる設計を想定。
  
#### ASGIサーバー

* Uvicorn

  * FastAPIの標準的なASGIサーバーであるため採用。

#### 開発環境

* Poetry

  * パッケージ管理と仮想環境管理を一元化できるため採用。

#### バージョン管理

* Git
* GitHub

  * ソースコードの変更履歴管理を行うため採用。

#### デプロイ

* Render

  * 低コストで利用でき、無料枠を活用しながら容易にデプロイできるため採用。

#### FastAPI・Jinja2のキャッチアップ状況

* FastAPI

  * ルーティング（GET/POST）の基本実装経験あり
  * SQLAlchemyを用いたデータベース連携を実装済み
  * Pydanticによるバリデーションを利用したAPI開発を実装済み
  * Swagger UIを利用したAPIの動作確認が可能
  * JWT認証や予約重複チェックなどの業務ロジックを実装予定

* Jinja2

  * 今後画面実装に向けてキャッチアップ予定
  * テンプレートエンジンとして利用し、フォームや画面遷移の実装を予定している

* JavaScript

  * 基本的な文法や書き方は理解しているが、実装経験は多くなく、自信はまだ十分ではない
  * MVPでは必要最低限の利用を想定している

#### 現在の習得状況

FastAPIを用いたAPI開発については、ルーティング、データベース連携、バリデーション実装まで完了しています。

一方で、Jinja2を用いた画面実装やJavaScriptによる動的な処理については、開発と並行してキャッチアップを進める予定です。

そのため、MVPでは会議室予約機能の完成を優先し、必要最小限の機能から段階的に実装を進めます。
